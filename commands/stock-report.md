# /stock-report — 종목 리서치 파이프라인

대상 종목: **$ARGUMENTS**

아래 5단계를 순서대로 실행한다. 각 단계의 산출물이 다음 단계의 입력이다.

## 1단계 — 종목 식별

- 종목명이 모호하거나 동명 기업이 있으면 **6자리 종목코드로 확정**하고 어느 법인인지 보고한 뒤 진행한다.
- 식별 실패 시 후보를 제시하고 멈춘다.

## 2단계 — 수집 애널리스트 3종 병렬 실행

**한 메시지에서 Agent 도구를 동시 호출**해 병렬로 돌린다(서로 의존성 없음). 각 프롬프트에 종목명·종목코드·오늘 날짜를 명시한다.

| 서브에이전트 | 담당 | 데이터 소스 | 산출물 |
|-------------|------|------------|--------|
| `fundamental-analyst` | 재무·실적·공시 | DART (환경변수 `DART_API_KEY` 필요) | 3개년 재무 요약표 + 코멘트 3줄 |
| `market-technical-analyst` | 주가·추세·거래 | FinanceDataReader (키 불필요) | 가격 요약표 + 추세 코멘트 2~3줄 |
| `news-sentiment-analyst` | 뉴스·이슈·심리 | WebSearch (키 불필요) | 핵심 이슈 3~5개 + 심리 한 줄 |

## 3단계 — 리스크 종합 (순차)

- 위 3종 결과를 모두 받은 뒤 `risk-manager`에 **3종 산출물 전문을 입력으로 전달**해 호출한다(pykrx로 시총·거래대금 보강).
- 산출물: 핵심 리스크 3가지 + 모니터링 포인트 + 마무리 고지.
- 3종 중 일부가 "확인 불가"여도 그 사실을 함께 넘긴다(정보 공백도 리스크).

## 4단계 — 리포트 작성

4개 결과를 종합해 `reports/{종목명}.md`로 저장한다. 구성:

**종목 개요 → 재무 요약(3개년 표) → 가격·추세 → 뉴스·심리 → 리스크 → 한 줄 종합**

### 가드레일 (모든 리포트에 항상 적용)

- 모든 수치 옆에 **(출처: 데이터명, 연도/날짜)** 표기 — 출처 없는 수치는 쓰지 않는다
- 데이터를 못 구하면 지어내지 말고 **"확인 불가"**, 출처 없는 뉴스·루머는 **"미확인"**
- **매수/매도/보유, 목표가, 비중 확대/축소** 등 투자 행동을 단정하는 표현 금지 — 판단 근거 정리(의사결정 지원)까지만, 최종 판단은 사람
- 첫머리에 **"무료 공개 데이터 기반 학습용"** 한 줄 명시
- 끝에 **데이터 출처·기준일 목록** 첨부
- 마지막에 **"본 자료는 학습용 분석이며 투자 권유가 아닙니다"** 문구 명시
- 문체는 "~입니다" 체로 통일

## 5단계 — 검증 게이트 (필수)

- `verification-analyst`에 `reports/{종목명}.md` 점검을 위임한다(정확성·일관성·완결성·근거/형식 4축).
- 검증 애널리스트는 직접 고치지 않는다 — 문제 표(위치·문제·수정 제안·심각도)와 **통과/보류** 판정만 반환한다.
- **보류**면 문제 표대로 리포트를 수정하고 재검증한다. **통과** 후에만 다음으로 진행한다.

## 6단계 — PPTX 생성 (선택)

- 사용자가 PPTX를 원하면(또는 처음부터 요청했으면) **`report-pptx` 스킬**을 호출해 `reports/{종목명}.pptx`를 생성한다.

## 단일 질의 라우팅 (전체 파이프라인이 아닐 때)

- "재무/실적/공시만" → `fundamental-analyst`
- "주가/이동평균/거래량만" → `market-technical-analyst`
- "뉴스/이슈/분위기만" → `news-sentiment-analyst`
- "리스크 종합만" → 가능하면 3종을 먼저 돌려 입력을 준 뒤 `risk-manager`
- "리포트 검증/점검만" → `verification-analyst`
